# Правила игры Кубовая Тыща

1. В игре побеждает участник, набравший 1000 или больше очков.
2. Игроки ходят по очереди.
3. У каждого игрока есть три броска и 5 кубиков.
4. Если на всех кубах есть очки, это небитка - несгораемая сумма, дающая ещё три броска.
5. Если очков за бросок не выпало вообще - это булка, сгорают все отложенные очки и броски.
6. Каждый ход игрок имеет право записать на счёт выпавшие очки или отложить любое количество кубов с очками, а остальные перекинуть.


# Комбинации очков:

5 одинаковых кубов - 1000 очков

4 одинаковых куба - 10х + 100 очков

3 одинаковых куба - 10х очков, за исключением трёх единиц - это 100 очков

из одного куба: единица - это 10 очков, пятёрка - 5 очков.

дубли из двоек, троек, четвёрок и шестёрок очков не дают, но закрываают до небитки, если на других кубах есть очки


# В игре также есть бочка:
если набрано больше девятисот очков, сумма замораживается и игроку нужно закрыться до 1000 с трёх бросков


# Команды
```bash
pip install -r requirements.txt
python main.py
python main.py --tours 200
python main.py --player greedy --player cautious:80 --player hopness:70:Риск
python main.py --seed 42 --json-out reports/report.json --csv-out reports/report.csv
python main.py --seed 42 --summary-only --json-out reports/summary.json
python plot_report.py --json reports/report.json --out-dir reports/charts
python plot_report.py --csv reports/report.csv --out-dir reports/charts
```

Формат `--player`:
- `greedy`
- `cautious:80`
- `hopness:70:ИмяИгрока`
- `adaptive:60:ИмяИгрока`
- `barrel:55:ИмяИгрока`

# Стратегии

Перевод названий стратегий:

- `greedy` - `жадная`
- `cautious` - `осторожная`
- `hopness` - `надежда на небитку`
- `adaptive` - `адаптивная`
- `barrel` - `бочка-ориентированная`

- `greedy`
  - Берёт самый дорогой набор очковых кубов из текущего броска.
  - Записывает очки сразу, как только может.
  - `threshold` для неё почти не важен и обычно используется значение `1`.

- `cautious`
  - Старается взять выгодный набор кубов, но решение о записи очков принимает осторожнее.
  - Обычно записывает ход, когда накопила `threshold` очков.
  - Может записать раньше, если бросков почти не осталось или риск булки уже высокий.
  - Это хороший базовый ориентир для сравнения других стратегий.

- `hopness`
  - Играет на небитку: старается отложить как можно больше кубов, чтобы оставить на столе минимум риска.
  - Дольше тянет ход и чаще рассчитывает на удачное продолжение серии.
  - На бочке закрывается только при реальной возможности добрать до `1000`.
  - `threshold` задаёт, с какого размера хода стратегия начинает чаще соглашаться на запись.

- `adaptive`
  - Балансирует между доходностью хода и риском булки.
  - Если риск булки маленький, играет жаднее и пробует добрать больше.
  - Если риск булки высокий или бросков мало, раньше фиксирует очки.
  - На практике хорошо работает с более низкими порогами, чем `cautious`.
  - По текущим прогонам сильным выглядит `threshold` около `45`.

- `barrel`
  - Специально учитывает бочку.
  - До бочки играет достаточно рационально, а рядом с `900` чаще фиксирует удобный вход в бочку.
  - На самой бочке стремится либо сразу закрыться, либо взять максимально полезный добор под закрытие.
  - По текущим прогонам сильными выглядят пороги в диапазоне `55-65`.

Кратко по-русски:

- `жадная` - берет максимум здесь и сейчас;
- `осторожная` - не жадничает и чаще фиксирует очки раньше;
- `надежда на небитку` - старается дожимать удачные серии;
- `адаптивная` - подстраивается под риск и число оставшихся бросков;
- `бочко-ориентированная` - играет с прицелом на вход и закрытие бочки.

Как читать `threshold`:
- это не “обязательная сумма записи” во всех случаях;
- у простых стратегий это почти прямой порог фиксации очков;
- у умных стратегий это базовая целевая сумма, которая может сдвигаться из-за риска булки, числа оставшихся бросков и состояния бочки.

Отчёт турнира включает:
- средний счёт по каждому игроку;
- частоту булок;
- частоту небиток;
- winrate по игрокам;
- winrate по стратегиям.

Дополнительные возможности:
- `--seed` делает турнир воспроизводимым;
- `--json-out` сохраняет сводку и статистику по партиям в JSON;
- `--csv-out` сохраняет построчную статистику по партиям в CSV для графиков.
- `--summary-only` экспортирует только сводку;
- `--per-game-only` экспортирует только статистику по партиям.

Графики:
- `plot_report.py --json ...` строит SVG-графики из JSON;
- `plot_report.py --csv ...` строит SVG-графики из CSV;
- в директории графиков создаются файлы `winrate_by_player.svg`, `average_score_by_player.svg`, `scores_by_game.svg`, `wins_by_player.svg`.
